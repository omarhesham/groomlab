# GroomLab viewport after an evaluation: before and after (2026-10-01)

The follow-up to [2026-10-01.md](2026-10-01.md)'s finding (the redraw after an evaluation cost
more than the evaluation). Same machine and setup; GroomLab only (`run_bench.py --parts gui
--systems groomlab,groomlab_follow`), main's build (4d2ad0a) against this change's, the two
alternating which goes first on each of 3 runs. Medians of 3 (min-max). Raw numbers:
`2026-10-01_viewport.json`.

## Where the time went (before, profiled)

`groomLabGraphStats -drawTimes` and Maya's profiler, noise tweak at 500k strands x 16 points
(100k in brackets):

| Step | ms |
| --- | --- |
| Evaluation (compute) | 160 (35) |
| Core build (`DisplayBuilder::update`): ~0.5 GB of vectors zero-filled, then frames | 100 (24) |
| Override: copying them single-threaded into new `MVertexBuffer`s | 54 (5) |
| `setGeometryForRenderItem` | 10 (0.1) |
| Maya's draw after it: making the new buffers and uploading their system-memory copies | ~235 (~65) |
| Tweak to redrawn frame | ~560 (~130) |

## What changed

- The strand lines are written straight into the items' buffers (`StrandLines`, display.h): no
  core vectors, no copy, every stream written in parallel.
- Each item keeps its buffers and writes them again in place; the buffers are GPU-only (no
  software-staged copy, which Maya committed in ~50 ms and uploaded again in the next draw).
- A strand item's indices and uvs stay while its point counts do: a tweak or a frame of
  playback writes positions, normals, tangents and bitangents only (48 of the 64 bytes a point).

Pixels identical: the viewport suite's 25 snapshots match main's, pixel for pixel.

The display update after an evaluation at 500k (37 ms) is: the builder ~9 ms (the old strand
set released, the lines' layout key, the overlays' pull), writing 384 MB of points and frames
into the GPU buffers ~25 ms, the rest acquire and commit. XGen's tweak-to-redraw at 500k was
132 ms on its 160 ms evaluation (2026-10-01.md), GroomLab's is now ~40 ms over its evaluation.

Orbit: the bench's single 60-frame orbit includes the first frames' warm-up and varies run to
run (main's 120-264). Four orbits of 60 frames in one session each (500k): main 260 / 322 / 318 /
320 fps, this change 262 / 324 / 321 / 319 fps: the same once warm. The steady draw is
unchanged; "redraw, nothing changed" right after creation is ~2 ms more here (the GPU still
taking the first upload).
